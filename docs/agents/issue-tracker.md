# Issue tracker: Ad-hoc (chat-reported)

This is a solo personal project. There is no formal issue tracker — no GitHub Issues, no local `.scratch/` ticket files.

## How issues surface

The user (sole developer) reports problems directly in conversation as they hit them — e.g. "I found a bug, X is happening." That message *is* the issue report.

## When a skill says "publish to the issue tracker" or "fetch the relevant ticket"

There is nothing to publish to or fetch from. Skills that assume a persistent tracker (`to-tickets`, `triage`, `to-spec`) don't have a natural home here — treat the current chat message as the full issue content and work from it directly rather than trying to create a file or a GitHub issue. Don't create `.scratch/` files or GitHub issues unless the user explicitly asks for one.
