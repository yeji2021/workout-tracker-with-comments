# 탭바 아래 여백 띠

## 증상

iOS 홈 화면(standalone PWA)에서 하단 탭바의 아이콘·라벨 아래로 넓은 빈 공간이 보인다. 데스크톱 브라우저 시뮬레이션으로는 재현이 안 되고 실기기에서만 나타남. 테마와 무관.

## 상태

**해결됨 (2026-08-17).** `bb65309` + `ae24109` 로 레이아웃을 고치고, 설정 → "최신 버전으로 새로 받기"로 서비스워커 캐시를 강제로 비운 뒤 실기기에서 사라진 것을 확인.

---

## 원인 — 두 겹이었다

### 겹 1. 레이아웃: 셸이 화면보다 58px 짧았다

iOS 홈 화면 앱이 **실행 직후 레이아웃 뷰포트를 실제 화면보다 ~58px 작게** 잡는다. 셸 높이를 `100dvh`(그 이전엔 `height:100%` 체인)로 잡았기 때문에 셸이 그만큼 짧아졌고, 셸 바닥에 붙은 탭바가 화면 바닥에서 58px 떠 있었다. 그 아래는 `html`/`body` 배경이라 **색이 같아** 틈이 아니라 "탭바 밑의 빈 여백"으로 보였다.

### 겹 2. 디자인: 안전영역 인셋을 그대로 패딩으로 썼다

`env(safe-area-inset-bottom)`(세로 34px)을 통째로 탭바 `padding-bottom`에 넣어, 라벨 아래가 34px 비어 있었다. 실제로 비켜줘야 하는 건 홈 인디케이터(바닥에서 8px 위, 높이 5px)뿐이다.

### 실측 (화면 녹화 프레임 + 스크린샷 픽셀 계측, 1179×2556 = 393×852@3x)

| 상태 | 탭 라벨 끝 (화면 바닥에서) |
|---|---|
| 버그 | **86.7px** |
| 웹 인스펙터 붙인 상태 | 27.7px |

탭바 상단선 129.3px − 탭바 높이 71.5px = **57.8px** (= 탭바 바닥이 화면 바닥에서 뜬 거리)
86.7 − 58 = 28.7 ≈ 27.7 → **탭바 내부는 멀쩡했고 셸이 짧았던 것**이 확정됨.

---

## 왜 몇 주가 걸렸나 — 진짜 병목은 배포가 아니라 캐시였다

고친 코드가 **기기에 도달한 적이 없었다.** `vite-plugin-pwa`가 `registerType: 'prompt'`이고 `index.html`이 precache되어 있어, 사용자가 업데이트 토스트를 눌렀다고 해도 새 SW가 waiting에서 넘어가지 않으면 **구버전 index.html → 구버전 해시 자산**이 계속 재사용된다. 설정의 **"최신 버전으로 새로 받기"**(SW unregister + caches 삭제 + reload)를 눌렀을 때 비로소 반영됐다.

**결정적 증거**: `bb65309`(패딩 34→20px)는 순수 CSS라 iOS 뷰포트 버그와 무관하게 무조건 14px이 줄어야 한다. 그런데 푸시 54분 뒤 스크린샷에서도 라벨 끝이 **86.7px 그대로**였다 → 기기가 그 이전 코드를 돌리고 있었다는 뜻.

## 두 번째 함정 — 계측이 증상을 지웠다

**맥 Safari 웹 속성 검사기를 붙이면 리레이아웃이 일어나 겹 1이 사라진다.** 그래서 콘솔로 잰 값이 전부 정상(`innerHeight 852 = screen 852`, `nav.bottom 852`, 바닥 1px = `NAV`)으로 나왔고, 이 값을 믿고 다섯 번 헛짚었다.

> 콘솔 측정값이 "정상"인데 사용자는 계속 문제를 본다면, **측정 행위 자체가 상태를 바꾸는지** 의심할 것. 그때는 화면 녹화가 유일한 증거다.

## 다음에 또 이런 일이 생기면 — 순서를 지킬 것

1. **설정 → 버전**을 먼저 본다. 기대한 커밋이 아니면 그건 코드 문제가 아니라 배포/캐시 문제다. 여기서 끝날 일에 CSS를 건드리지 않는다.
2. **화면 문제는 눈으로 보기 전에 고치지 않는다.** 스크린샷/녹화를 받아 픽셀로 잰다. 수치만 믿고 고치면 안 된다.
3. 실기기 전용 현상은 **웹 인스펙터를 붙이는 순간 사라질 수 있다.** 콘솔이 정상이라고 나오면 녹화로 교차검증한다.
4. 사용자가 쓴 단어를 그대로 성립시키는 가설을 먼저 검토한다. "패딩"은 정말 패딩이었다.

## 검증 도구 (재현·회귀 확인용)

Xcode/iOS 시뮬레이터는 이 맥에 없다. 대신:

- **Playwright WebKit** (iOS Safari와 같은 엔진) + `devices['iPhone 14 Pro']` + `--safe-top/--safe-bottom` 주입
- **온보딩 우회**: `localStorage['wt_profile']`에 `{profile_id, nickname, groups:[]}` 주입하면 네트워크 없이 실제 앱이 뜬다
- **뷰포트 축소 재현**: viewport를 794(=852−58)로 주고 `navigator.standalone`/`screen.height`를 흉내내면 겹 1이 그대로 재현된다. `ae24109` 검증은 이 방식으로 5개 시나리오(일반 브라우저 / standalone 정상 / standalone 58px 짧음 / 가로 / 짧은 창) 통과
- **영상 프레임 추출**: 번들 ffmpeg는 MP4를 못 읽는다. WebKit 페이지에 `<video>`를 띄우고 `currentTime`을 옮기며 canvas로 뽑는다. 압축 노이즈 때문에 세로 한 줄이 아니라 **가로 평균 휘도**로 경계를 재야 한다
